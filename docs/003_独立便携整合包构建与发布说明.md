# 003 独立便携整合包构建与发布说明

本文档说明如何将 **YoloStudio** 打包为面向 **无 Python 环境 Windows x64 电脑** 的独立便携整合包（方案 A），使终端用户解压后双击 `YoloStudio.exe` 即可开箱使用「视频抽帧 → 原生标注工作台 → LLM / SAM 3 智能标注 → YOLO26 训练/验证/导出」全流程。

---

## 1. 交付产物结构

执行打包脚本后，默认在 `dist/YoloStudio-v<版本号>-win64-<gpu|cpu>/` 下生成完整的绿色免安装目录（可进一步一键压缩为 `.7z` 或 `.zip`）：

```text
YoloStudio-v0.3.0-win64-gpu/
├── YoloStudio.exe                              # 原生无黑框桌面启动器（带应用图标、PE 版本属性与防篡改校验）
├── YoloStudio-CLI.cmd                          # 无头批处理命令行入口（转发参数至 app\cli.py）
├── 使用说明_请先解压后双击YoloStudio运行.txt     # 面向终端用户的简明启动指引
├── runtime/                                    # 内置独立 Python 3.12 运行时、第三方依赖与 MSVC 运行库 DLL
│   └── Lib/site-packages/yolo_studio_portable.pth
├── app/                                        # YoloStudio 核心应用源码（与用户数据隔离）
│   ├── main.py
│   ├── cli.py
│   └── src/yolo_studio/
├── weights/                                    # 本地预置预训练权重目录（如 yolo26n.pt、yolo26s.pt）
├── workspace/                                  # 默认用户工作区（抽帧 data/、数据集 datasets/、训练 runs/）
├── docs/                                       # 项目使用说明文档
├── LICENSE                                     # GPL-3.0-only 开源许可证
└── THIRD_PARTY_NOTICES.md                      # 第三方软件与开源协议声明
```

## 2. 一键构建命令

在仓库根目录下打开 PowerShell，根据发版场景选择以下两种模式之一：

### 2.1 模式一：从本机 `.venv` 离线快速打包（`from-venv`，默认）

适合开发机 `.venv` 已安装好完整依赖、希望免流量快速生成分发包进行内测或团队共享：

```powershell
# 仅生成便携包目录并执行隔离环境自检
.\scripts\build_portable.ps1

# 生成便携包目录并调用 7-Zip 自动打包为单文件 .7z 压缩包
.\scripts\build_portable.ps1 --archive 7z

# 若本机 .venv 中曾混装 opencv-python，可附加 --fix-opencv 在便携包内联网重装纯 contrib-headless
.\scripts\build_portable.ps1 --fix-opencv --archive 7z
```

### 2.2 模式二：从纯净独立 Python 全新构建（`clean`，推荐正式对外发版）

自动拉取官方 `python-build-standalone`（CPython 3.12 Windows x64）或复用本机 `uv` 独立运行时，从零安装指定变体依赖并自动消除 `opencv-python` 与 `opencv-contrib-python-headless` 冲突：

```powershell
# 1) 构建 GPU 完整版（默认采用 PyTorch cu126，并预下载内置 yolo26n.pt / yolo26s.pt）
.\scripts\build_portable.ps1 --mode clean --variant gpu --download-weights yolo26n.pt yolo26s.pt --archive 7z

# 2) 构建 CPU 轻量版（适合无 NVIDIA 独显、仅做抽帧 + 标注 + 云端 LLM 智能标注的电脑，体积大幅减小）
.\scripts\build_portable.ps1 --mode clean --variant cpu --download-weights yolo26n.pt yolo26s.pt --archive 7z

# 3) 使用国内 PyPI 镜像源加速常规依赖下载
.\scripts\build_portable.ps1 --mode clean --variant gpu --pip-index-url https://pypi.tuna.tsinghua.edu.cn/simple --archive 7z
```

### 2.3 模式三：日常迭代极速构建（`--patch-only` / `--reuse-runtime`，推荐）

当本机已构建过一次便携包、后续仅修改了界面或业务逻辑（未增删第三方 Python 依赖）时，无需反复重建数 GB 的 `runtime/`：

```powershell
# 1) 极速纯补丁发版（约 55 秒完成）：自动递增版本号、只读挂载已有 runtime/ 编译 .pyd 与 YoloStudio.exe、跑完冒烟自检并输出 ~5.6 MiB 补丁包
.\scripts\build_portable.ps1 --bump patch --patch-only --variant cpu --protect pyd --archive 7z

# 2) 复用未变更的预编译运行库底座构建完整包（约 2 分钟完成）：自动比对依赖指纹跳过 pip 与 4 万文件 compileall，配合 fast 极速压缩
.\scripts\build_portable.ps1 --bump patch --mode clean --variant cpu --protect pyd --reuse-runtime --archive 7z --compression fast --patch-archive

# 3) 若首次从升级脚本前的旧版目录复用，可显式传入 --runtime-source 承接底座（后续将自动通过指纹印章命中）
.\scripts\build_portable.ps1 --mode clean --variant gpu --protect pyd --reuse-runtime --runtime-source dist\YoloStudio-v0.3.3-win64-gpu --archive 7z --compression fast
```

### 2.4 常用构建参数一览 (`scripts/build_portable.py`)

| 参数 | 说明 | 默认值 |
| :--- | :--- | :--- |
| `--mode` | `from-venv`（克隆本地虚拟环境）或 `clean`（全新纯净安装） | `from-venv` |
| `--variant` | `gpu`（CUDA 版）或 `cpu`（纯 CPU 轻量版） | `gpu` |
| `--protect` | 源码保护级别：`pyd`（Cython 编译自研核心为原生 `.pyd` 机器码 + 剥离 `.py` + 硬编码 SHA-256 防篡改校验，推荐内部防查看/防篡改）、`pyc`（仅留同级 `.pyc` + 防篡改校验）或 `none`（保留明文源码，用于开源合规对外分发） | `pyd` |
| `--bump` | 构建前自动递增单一版本源 `src/yolo_studio/_version.py`（`patch` / `minor` / `major`） | 不递增 |
| `--set-version` | 构建前显式将单一版本源设为指定语义化版本号（如 `0.3.1`，与 `--bump` 互斥） | 不修改 |
| `--output-root` | 构建产物输出父目录 | `dist` |
| `--weights` | 拷贝至便携包 `weights/` 的一个或多个本地 `.pt` 文件路径 | 自动扫描仓库根与 `weights/` |
| `--download-weights` | 构建期间自动下载并内置至 `weights/` 的官方权重文件名 | 空 |
| `--torch-index-url` | `clean` 模式下自定义 PyTorch 轮子源（如切换 `cu124` / `cu128`） | `gpu` 用 `cu126`，`cpu` 用 `cpu` |
| `--pip-index-url` | `clean` 模式下自定义常规依赖镜像源地址 | 官方 PyPI |
| `--standalone-python-archive` | `clean` 模式下手动指定离线下载好的独立 Python `.tar.gz`/`.zip` | 自动下载并缓存于 `build/portable_cache` |
| `--fix-opencv` | `from-venv` 模式下联网修复 OpenCV 双包覆盖问题 | 关闭（`clean` 模式始终自动执行） |
| `--archive` | 归档压缩格式：`none`、`7z` 或 `zip` | `none` |
| `--compression` | 压缩档位：`fast`（7z `-mx=1 -ms=off` / zip 1 级，极速内测）、`normal`（7z `-mx=5` / zip 6 级，均衡）、`max`（7z `-mx=7` / zip 9 级，高压缩率） | `normal` |
| `--patch-archive` | 完整构建完成后额外生成扁平目录结构的轻量热更新补丁包（仅含 `YoloStudio.exe` + `app/` + `docs/` 与 `.pth` 路由，供旧版直接覆盖升级） | 关闭 |
| `--reuse-runtime` | 按与业务版本号解耦的依赖指纹自动复用本地已预编译 `runtime/` 底座（原地零拷贝保留或 16 线程 `robocopy` 并行克隆），跳过依赖重装与全量字节码编译 | 关闭 |
| `--patch-only` | 极速纯补丁发版模式：通过 Windows 目录联接（`mklink /J`）零拷贝只读挂载已有 `runtime/`，仅编译应用代码与启动器、跑完隔离冒烟自检并直接输出补丁包 | 关闭 |
| `--runtime-source` | 可选：为 `--reuse-runtime` 或 `--patch-only` 显式指定本地已有的便携包根目录或 `runtime/` 目录 | 自动检索 |
| `--skip-smoke-test` | 跳过构建末尾的隔离进程启动与导入自检 | 关闭 |

## 3. 核心工程设计说明

1. **零绝对路径残留与多进程兼容**：
   - 构建工具自动移除 `pyvenv.cfg`、`__editable__*.pth`、`*.egg-link` 与 `*.dist-info/direct_url.json`，并在 `runtime/Lib/site-packages/yolo_studio_portable.pth` 写入纯相对路径（`../../../app/src`）。
   - 该机制在解释器初始化期生效，保证 Windows 下 PyTorch `DataLoader(workers > 0)` 以 `spawn` 方式拉起的训练工作子进程同样能准确加载包内模块。
2. **宿主环境隔离与未解压防护**：
   - `YoloStudio.exe`（源码位于 `packaging/launcher/YoloStudioLauncher.cs`，由系统内置 `csc.exe` 编译）在启动前自动清除宿主电脑可能存在的 `PYTHONHOME`、`PYTHONPATH`、`VIRTUAL_ENV`、`CONDA_PREFIX` 变量，并设置 `PYTHONNOUSERSITE=1` 与 `PYTHONUTF8=1`，防止目标电脑上残留的旧版 Python 或 Conda 环境干扰运行。
   - 若用户未解压压缩包而直接在压缩软件预览窗口双击 `YoloStudio.exe`，启动器会检测到 `runtime\pythonw.exe` 缺失并弹出中文指引提示框；启动期若遇异常，可通过 `YoloStudio.exe --console` 打开终端排障或查看 `workspace/logs/startup_crash.log`。
3. **代码与数据解耦及只读目录自动回退**：
   - 便携包内 `app/`（只读代码）与 `workspace/`（用户抽帧、数据集、训练输出）分离；若用户将便携包放置在受系统权限保护的只读目录（如 `C:\Program Files\YoloStudio`），程序启动时会自动回退至 `~/Documents/YoloStudio` 作为默认工作区，避免写入报错。
4. **冷启动秒开优化机制**：
   - **瞬时视觉反馈**：`QApplication` 初始化后立即展示高分屏圆角启动欢迎图（`QSplashScreen`），消除双击后的空白等待期。
   - **首屏零重型阻塞**：主窗口以 `lazy_init=True` 秒开「1. 视频抽帧」首屏；原生 PyQt6 标注工作台零重型第三方依赖即刻就绪，`torch` 计算设备检测推迟至主窗口上屏后由后台 `DeviceProbeWorker` 异步完成并无损刷新设备状态。
   - **字节码预编译**：构建阶段自动执行多核并行 `compileall` 预生成 `app/` 与 `runtime/Lib/` 的 `.pyc` 字节码缓存，免去终端用户首次启动时的源码编译与小文件落盘开销。
5. **源码防查看与防篡改保护（`--protect pyd`，默认启用）**：
   - **核心业务编译为原生机器码**：借助本机 Visual Studio C++ Build Tools 与缓存的独立 `Cython` 工具链（不污染目标便携包 `site-packages`），将 `src/yolo_studio/**/*.py` 全部编译为平台原生 x64 `.pyd`（C 扩展 DLL）并彻底清除明文 `.py` 与 `.c` 中间文件。
   - **硬编码 SHA-256 防篡改拦截**：构建收尾自动采集 `app/main.py`、`app/cli.py`、`yolo_studio_portable.pth` 及全部核心 `.pyd` 的 SHA-256 指纹并直接编译进 `YoloStudio.exe` 内部常量；每次启动 GUI（`YoloStudio.exe`）或 CLI（`YoloStudio-CLI.cmd`）前在 `< 15 ms` 内自动校验，检测到任何文件缺失或被修改即弹窗/报错拒绝启动。
   - **构建机路径零残留**：构建阶段自动移除 `runtime/Scripts` 下 `pip` 生成的含构建机绝对路径包装器（如 `yolo.exe`、`torchrun.exe`）。
   - **开源对外分发模式**：若面向外部第三方按 `GPL-3.0-only` 开源分发，请显式传入 `--protect none` 保留完整可读源码。
6. **单一版本源全链路同步**：
   - 全项目版本号统一定义在 `src/yolo_studio/_version.py`，`pyproject.toml`（动态版本）、桌面主窗口标题栏、启动欢迎图、CLI `--version`、压缩包文件名及 `YoloStudio.exe` 的 Windows PE `FileVersion` / `ProductVersion` 均自动联动该版本。
   - 后续迭代发版时，仅需在构建命令中附加 `--bump patch`（修复/优化）或 `--bump minor`（新增特性）即可自动升号打包，避免同名覆盖旧包。
7. **轻量补丁热更新（`--patch-archive` / `--patch-only`）**：
   - 后续修复界面或核心逻辑（未新增第三方 C 扩展依赖）时，可直接运行 `--patch-only`（或在完整打包命令中附加 `--patch-archive`）在 `dist/` 下自动产出轻量升级补丁包（如 `YoloStudio-v0.3.3-win64-patch.7z`，通常仅 ~5.6 MiB）。
   - 已部署旧版的同事关闭程序后，只需将补丁包直接解压覆盖到旧版根目录（同时替换 `YoloStudio.exe` 与 `app/`），即可秒级完成升级并完整保留 `workspace/` 历史数据与 `weights/` 权重。
8. **构建提速、多线程复制与底座依赖指纹复用**：
   - **16 线程原生目录复制**：Windows 下自动调用 `robocopy /E /COPY:DAT /MT:16` 替代单线程 `shutil.copy2` 复制大目录（如 4.6 万文件的 `site-packages` 与底座克隆）。
   - **版本号解耦的底座指纹（`--reuse-runtime`）**：每次完整构建在 `runtime/.yolo_studio_runtime_stamp.json` 中记录由构建模式、硬件变体、Python/PyTorch 源与 `requirements.txt`/`pyproject.toml`/`.venv` 三方包清单计算的 SHA-256 指纹（刻意忽略 `src/yolo_studio/_version.py` 与测试包）。依赖不变时自动原地保留或并行克隆已预编译好的 `runtime/`，跳过 `pip install`、OpenCV 重装与 4 万文件 `compileall`。
   - **零拷贝只读挂载极速补丁（`--patch-only`）**：在临时工作区通过无需管理员权限的 Windows 目录联接（`mklink /J`）挂载现成 `runtime/`，全过程注入 `PYTHONDONTWRITEBYTECODE=1` 保障源目录零写入，仅耗时约 **55 秒**即可完成 18 个 `.pyd` 编译、SHA-256 防篡改启动器生成、全套隔离 GUI 冒烟自检与 `.7z` 补丁打包并在结束时安全卸载联接点。
   - **可调压缩档位（`--compression fast|normal|max`）**：内测发版可选 `fast`（7-Zip `-mx=1 -ms=off -mmt=on`）大幅缩短数 GB 归档耗时；正式对外归档保留默认 `normal`（`-mx=5`）或指定 `max`（`-mx=7`）。

## 4. 目标用户电脑运行要求与开源合规清单

### 4.1 终端电脑环境要求
- **操作系统**：Windows 10 / Windows 11 64 位（x86_64）。
- **无需用户安装**：Python、CUDA Toolkit、cuDNN（已内置并由应用自动配置 `torch\lib` 搜索路径）、FFmpeg（OpenCV 已内置解码动态库）、VC++ 运行库（构建阶段已将 `vcruntime140*.dll`、`msvcp140*.dll`、`concrt140.dll`、`vcomp140.dll` 随包补齐至 `runtime/`）。
- **显卡驱动（仅 GPU 加速需要）**：使用 NVIDIA 显卡运行本地 SAM / SAM 3 自动标注或 YOLO26 本地 GPU 训练时，目标电脑需已安装常规 NVIDIA 显卡驱动（基于 `cu126` 构建时建议驱动版本 `>= 560.xx`，基于 `cu124` 构建时建议 `>= 531.xx`；无 NVIDIA 独显或驱动不支持时会自动回退至 CPU 模式运行）。

### 4.2 开源协议合规要求
- 因使用 `PyQt6`（`GPL-3.0`）与 `ultralytics`（`AGPL-3.0`）且本项目采用 `GPL-3.0-only` 协议，对外分发便携整合包时**必须保留根目录下的 `LICENSE`、`THIRD_PARTY_NOTICES.md` 以及 `app/` 内的完整对应源码**（对外公开分发请使用 `--protect none`，请勿在二次分发时手动删除许可文件）。
